# 素材区使用指南

本机位置：`F:\website\Nuwanda-space\materials`

现在是“素材 → 自动读取 → 页面展示”三层结构。你负责放照片、写内容；系统负责收集、排序与排版。以前需要修改 `src/data/life.ts` / `content.ts` 数组的方式已停用，它们现在只是兼容接口。

## 一、最常用的操作：加一条生活记录

1. 用资源管理器打开 `F:\website\Nuwanda-space\materials\life`。
2. 新建一个文件夹，例如 `2026-10-18-秋日散步`。建议用“真实日期-你想起的标题”；中文可以，没有日期也可以。
3. 把照片原图复制进这个文件夹，保留 JPG / JPEG / PNG / WebP / AVIF 格式即可。无需手动缩放或压缩。
4. 新建 UTF-8 文本文件，命名为 **index.md**，写下你想表达的内容并保存。可以只有一段话。注意不要保存成 `index.md.txt`；Windows 可在“查看 → 显示 → 文件扩展名”中显示完整后缀。
5. 开发服务运行时，浏览器会自动刷新。没有运行服务时，按下面“本地查看”启动。

手机照片如果是 HEIC，请先导出为 JPG；当前自动图片入口不识别 HEIC。文件夹内可以放多张照片，页面会为它们生成适合屏幕的尺寸，原图继续保留。

完成后，目录像这样：

```text
materials/life/2026-10-18-秋日散步/
├─ index.md
├─ 01-树下的落叶.jpg
├─ 02-路边的长椅.jpg
└─ 03-回家的路.jpg
```

`index.md` 的最小内容：

```markdown
今天走了一条平时很少经过的小路，树叶已经开始变黄。

想把这些普通的片刻留下来。
```

**不需要**修改任何页面、组件、TypeScript 数组、图片导入或文章注册表；也不需要自己决定图片几列、字号、留白、卡片形状。

只放照片、不放 `index.md` 的目录不会生成记录。这可以避免把尚未整理的散图自动当成已完成内容。每个文件夹代表一件你想表达的事情，不是页面排版要求。

## 二、笔记和国旗护卫队使用完全相同的方法

| 想增加的内容 | 放到哪里 | 最少需要什么 |
| --- | --- | --- |
| 生活记录、一次出游、一个相册组 | `materials/life/你起的文件夹名/` | `index.md`，照片可选 |
| 学习笔记、读书记录、原创文章 | `materials/notes/你起的文件夹名/` | `index.md`，照片可选 |
| 一次升旗、训练、团队活动 | `materials/guard/你起的文件夹名/` | `index.md`，照片可选 |
| 修改个人介绍、关键词 | `materials/site/profile.json` | 修改对应文字，保留 JSON 引号与逗号 |

一篇笔记的完整正文会在列表中通过“展开正文”查看。专题一条事件支持多张照片，不限于首张。不提供照片时仍可展示文字，不会请求不存在的图片。

也可以从 `materials/_templates/` 复制整个对应模板文件夹，放到 life / notes / guard 并重命名。模板默认 `draft: true`，写好后改成 `draft: false` 才显示；`_templates/` 本身不会进入页面。

## 三、可选说明：覆盖自动标题、日期或添加分类

不写下面这些说明也可以。需要时，把它们放在 `index.md` 最开头，使用两行 `---` 包起来：

```markdown
---
title: 秋日散步
date: '2026-10-18'
category: 校园日常
summary: 一次傍晚的散步，几张关于秋天的照片。
draft: false
---
这里开始写正文。
```

| 字段 | 用途 | 不填时 |
| --- | --- | --- |
| `title` | 你给内容起的标题 | 从文件夹名称提取 |
| `date` | 内容真实发生/写作日期 | 从文件夹开头的 YYYY-MM-DD 提取；没有则不显示日期 |
| `category` | 内容分类 | 使用模块默认说明 |
| `summary` | 笔记列表摘要 | 从正文首段自动提取，最多 140 字符 |
| `draft` | true 暂不在页面展示 | false，展示 |
| `demo` | true 明确标记为演示 | false，按真实内容显示 |

所有记录自动按日期倒序排列，未提供日期的放后面；相同日期按稳定标识排列。不需要手工插入到某个数组位置。日期必须有效，诸如 2026-02-30 会明确报错，不会默默改成另一个日期。

## 四、图片的顺序、说明和复用

同一文件夹内的图片会自动收集，自然排序（1、2、10，而不是 1、10、2）。想指定顺序可在原文件名前加 `01-`、`02-`；不关心顺序则保持文件名即可。标题、日期与照片编号表达内容关系，不包含网格、颜色或裁切坐标。

默认替代文本由记录标题和图片文件名生成，建议使用描述性文件名。如果相机原名不能表达画面，可以选填图片说明：

```yaml
photos:
  01-树下的落叶.jpg:
    alt: 一棵梧桐树下，黄色落叶铺满石板路
    caption: 傍晚的小路
```

这段也放在文件开头的 `---` 内。`alt` 用于替代文本，`caption` 是可见图注。照片压缩、多尺寸、懒加载由展示层处理，原图不被覆盖。

进阶可选：同一张照片想在多个内容里使用时，无需搬动或复制，在另一条记录的说明里写相对引用。下面是仓库已有的训练记录复用例子：

```yaml
images:
  - ../../life/2026-10-15-evening-training/02-training.jpg
```

提供 `images` 时按这个列表选图与排序；不提供时自动使用当前文件夹的所有照片。只引用素材区内已有图片；路径失效会明确报错。

当前不要单独重命名或移动已被其他内容引用的图片；这属于内容关联变更，需同步引用。普通新增素材不需要进行这些操作，换网站风格也不会涉及它们。

## 五、本地查看，和“上传”的区别

在本机更新，就是**把文件复制到上述素材目录并保存**，无需 HTTP 上传、数据库或管理后台。手机素材可以通过数据线、文件传输或直接在聊天上传原图；也可以把原图放在你方便的本机文件夹，再告诉我绝对路径和文字，我来放入素材区。只有散图而未提供发生时间或说明时，不会替你编造经历。

开发预览：在项目目录打开 PowerShell，运行：

```powershell
.\scripts\local.ps1 run dev
```

访问终端输出的 Local 地址，通常是 `http://127.0.0.1:4321/`。开发服务会监听新增的 index.md 与图片；如果新增目录没有马上反映，重启该开发命令即可，无需修改代码。

构建后预览（如 4322）不会因为保存源文件就更新，需要重新构建并重启预览进程。以后发布到公网也需要单独的构建与部署；本次没有进行部署。

检查素材与站点：

```powershell
.\scripts\local.ps1 run check
.\scripts\local.ps1 test
.\scripts\local.ps1 run build
```

开发维护者还可以运行 `test:materials`：它会临时在三个模块各增加一条记录和图片，构建验证自动接入及草稿隐藏，清理临时文件后重建正常站点。运行期间请不要同时编辑这些验收临时目录或启动另一个构建。

## 六、以后换风格需要动什么

| 层级 | 文件位置 | 换风格时 |
| --- | --- | --- |
| 原图、正文、标题、日期与说明 | `materials/` | 不动 |
| 自动读取、校验、草稿过滤 | `src/content.config.ts`、`src/lib/materials*` | 通常不动 |
| 全站导航与模块配置 | `src/data/site.ts` | 根据新结构调整 |
| 封面选图、裁切焦点 | `src/data/presentation.ts` | 可以调整，原图不用动 |
| 页面组织、网格、字体、配色 | `src/components/`、`src/layouts/`、`src/styles/`、`src/pages/` | 在这里修改 |

例如生活从双栏换成单栏、文章从列表换成卡片、专题换成另一种时间线，都由组件和 CSS 改变。素材文件不存列数、颜色、字号或 CSS 类名。

## 七、已有素材如何处理

本轮把四张现有照片**逐字节复制**到素材区，正文和演示标记迁入各自 index.md；没有改动原图内容。旧 `src/assets/photos/` 原图保留作兼容留存，今后以 `materials/` 为新增/更新入口，不用维护两份。原数据文件迁移前的副本在 `.local/materials/legacy-data/`，不进入网站。

完整检查证据保存在 `.local/materials/`。这次的结构目标是独立内容库，并未增加云端上传、编辑后台、数据库或站内风格切换按钮。
